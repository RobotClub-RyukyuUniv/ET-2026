# ETロボコン2026 開発リポジトリ

このリポジトリは、ETロボコンに出場する琉球大学ロボットクラブのメインプログラムを管理する場所です。
公式の `etrobo` 環境の `workspace` 配下に配置して開発を行います。

## 📂 ディレクトリ構成
ETロボコンのビルド仕様により、このリポジトリ内のファイルは公式フレームワークの `workspace/` の**直下（1階層目）**に配置される必要があります。

```text
.
├── Makefile        # ビルド用設定ファイル
├── app.c / app.cpp # メインのソースコード
├── sample/         # 機能のサンプルコード・動作確認用
└── uml/            # 設計図（.drawio.svg）

```

---

## 🛠 1. 環境構築（初回のみ）

公式環境（`etrobo`本体）を汚さないように、本リポジトリは `workspace` の中にクローンして名前を変更して配置します。

**【手順】**

1. ターミナルを開き、公式の `workspace` の外（ホームディレクトリ等）にこのリポジトリをクローンします。
```bash
git clone git@github.com:RobotClub-RyukyuUniv/ET-2026.git

```


2. クローンしたディレクトリを、公式環境の `workspace/` 直下に移動させ、任意のアプリ名（例: `et-2026`）に変更します。
```bash
mv ET-2026/et-2026 ~/etrobo/workspace/et-2026

```

## 🚀 2. プログラムの実行方法

開発中は、**シミュレータ**と実機（SPIKE Prime）の両方を使用します。すべてのコマンドは `etrobo` 環境のルートディレクトリ上で実行してください。

### 💻 A. シミュレータで動かす場合

以下のコマンドを実行すると、コンパイルが行われシミュレータが起動します。

```bash
# 初回、または別のプログラムから切り替える場合（アプリ名を指定）
make app=et-2026 sim up

# 2回目以降（直前に実行したプログラムを再実行する場合）
make sim up

```

---

### 🤖 B. 実機（SPIKE Prime）で動かす場合

実機で動かす場合は、環境を「SPIKE-RTモード」にし、ロボットを「DFUモード」でPCに繋ぐ必要があります。

#### ① SPIKE-RTモードへの切り替え（初回のみ）

etrobo環境から以下のコマンドを実行し、環境を再起動させます。

```bash
touch SPIKE_RT

```

#### ② ロボットをDFUモードにする

ファームウェア（プログラム）を書き込むため、毎回以下の手順でPCと接続します。

1. SPIKE Primeハブの**電源を切り、USBケーブルを抜く**。
2. ハブ表面右上の「Bluetoothボタン」を長押しし続ける。
3. ボタンを押したまま、USBケーブルでPCと接続する。（ボタンの周りが紫色に点灯しても押し続ける）
4. ボタンの周りが**カラフルに変化し始めたら離す**。（これでDFUモード完了！）
※ ChromeOSやWindowsの場合は、OS側のUSB接続許可のダイアログが出たら適宜承認してください。

#### ③ ビルドと転送（アップロード）

DFUモードで接続できたら、以下のコマンドでプログラムのコンパイルと実機への転送を同時に行います。

```bash
# 初回、または別のプログラムから切り替える場合
make app=et-2026 up

# 2回目以降（直前に実行したプログラムを再実行する場合）
make up

```

## 📐 3. UML（設計図）の管理ルール

UML等の設計図は `uml/` ディレクトリ内で管理します。

* **使用ツール:** draw.io
* **保存形式:** `.drawio.svg` （Gitで差分が分かりやすく、GitHub上でそのまま画像としてプレビューできるため）
* **推奨環境:** VSCode拡張機能「Draw.io Integration」をインストールしてください。エディタ内で直接図の編集と保存が可能です。

## 🔄 4. GitHub運用ルール（コード管理）

「常に動く状態を保ち、必ずレビューを通してから本番に合流させる」ためのルールです。

### 📌 3つのブランチ

1. `main` （本番用）
* 常にエラーなく動き、大会で使える最新コード。**直接のPushは絶対NG。**


2. `feature/○○` （タスク用）
* 各メンバーの開発作業場（例: `feature/linetrace`）。完成したら `main` へPull Request (PR) を出す。
* 自分がどんどんタスクを追加していく予定なので、開発する時はそのブランチに移動する。


3. `playground` （実験用）
* 壊れてもいいお試し用ブランチ。ここで実験し、本番実装時は改めて `feature/` を作り直す。



### 🔁 開発の基本サイクル

1. 最新の `main` を取得: `git pull origin main`
2. 作業ブランチを作成: `git checkout -b feature/タスク名`
3. コードを書いて保存: `git add .` → `git commit -m "変更内容"` → `git push origin feature/タスク名`
4. GitHub上で **Pull Request (PR)** を作成。
5. 他メンバーにレビューしてもらい、問題なければ `main` にマージ！

## 📋 5. タスク管理ルール（GitHub Projects）

「今、誰が、何をしているか」を見える化するため、GitHub Projects（カンバン）を使用します。

* **Todo:** やるべきこと（Issue）置き場。
* **In Progress:** 誰かが作業中のタスク。
* **Done:** 完了したタスク。

### 📝 作業の流れ

1. **Issueを立てる**: 「1〜2日で終わるサイズ」に細分化してTodoへ追加（例：「カラーセンサで黒を検知して止まる」）。
2. **アサインする**: 作業を始める人は、自分をAssigneesに設定し、カードを `In Progress` に移動。
3. **自動クローズ**: PRを出す際、説明欄に `Closes #Issue番号` と書く。PRがマージされると自動でDoneに移動します。
